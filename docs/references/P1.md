# 一、接下來可以做什麼

P0 結束了，但 **P1 不是「開始寫程式」，是先做一輪設計決策**。目前擋著 P1 的有四份，而且**全部不需要再量，現在就能決定**：

| 決策 | 內容 | 為什麼現在能定 |
|---|---|---|
| **`DOC-0001`** | node tree 形狀、stable ID、**composing region 放在模型哪裡** | 純設計，所有東西都掛在它上面，必須第一個 |
| **`LAY-0002`** | 失效傳播與偏移結構（前綴和 / 延遲物化） | P0 已證實這是缺口；解法是已知的資料結構，不需 spike |
| **`EDT-0001`** | selection 型別數量與語意、undo 合併規則 | 純設計；型別數量是成本的乘數，要先鎖 |
| **`BND-0001`** | display list 的二進位格式與版本策略 | 形狀已被 `FND-0002` 約束，剩下的是格式定義 |

順序：**`DOC-0001` 必須先**，其餘三份可並行。

還有一項沒量但不擋路：**Flutter 自身的每幀佔比**。它只影響診斷指標的校正，主要 gate（不掉幀）在 P1 自然會測到。

# 二、分工原則：不是難易度，是這兩個軸

用「難的給人、簡單的給 AI」會分錯。正確的軸是你自己的 `FND-0001` 已經寫下的那條，加上一條：

|  | **答案已知** | **答案要被發明** |
|---|---|---|
| **錯誤可見** | AI 全包 | AI 做，人快速看 |
| **錯誤靜默** | AI 寫，**人必須讀得懂** | **人主導設計** |

**右下角那格就是你的學習清單**——因為那些正好是「必須由你發明、而且錯了不會有徵兆」的東西。

**左下角是你必須學會閱讀 C++ 並行與記憶體程式碼的理由**：即使 AI 寫，你是唯一的閘門。

# 三、人類清單（＝學習清單，依學習密度排序）

| 項目 | 學習價值 | 為什麼是你 |
|---|---|---|
| **流式 ＋ 空間統一模型** | ★★★★★ | **沒有教科書答案。** 這是整個專案最原創的部分，也是最容易被 AI 做成「兩套各自合理但無法統一」的東西 |
| **失效傳播與偏移結構**（Fenwick／order-statistic tree） | ★★★★★ | 經典資料結構、自成一體、**實作只有一百多行但概念密度極高**。P0 已證實這是真缺口，不是假想題 |
| **並行交接與 lock-free 環形日誌**（spike3 選的策略 C） | ★★★★★ | **靜默錯誤之王。** 並行 bug 不會有徵兆，只會在使用者資料上顯現。你是核准者，這格不能外包判斷 |
| **composing region 與 IME 正確性** | ★★★★ | **只有你能判斷對錯**——你天天用注音，AI 沒有那個回饋迴圈 |
| **undo 合併規則與交易原子性** | ★★★★ | 規則要被發明（三種內容的 undo 單位不同），且錯了是靜默的 |
| **ink 資料模型** | ★★★★ | 你已經說要親手做 |

**共同特徵：小而深。** 加起來可能不到全專案 15% 的行數，但佔學習價值的 80%。

# 五、灰區怎麼處理

有兩項是「你設計、AI 實作、你逐行審」：

- **增量失效的實際實作**（你定結構，AI 寫程式碼）
- **背景執行緒的交接**（你定契約，AI 寫，但**並行程式碼你必須自己讀完**）

處理方式：**審查清單直接從 ADR 生成**。例如 `FND-0002` 的四項判準（C 型別、status code、執行緒契約、釋放責任）就是 C ABI 程式碼的 review checklist——這正是你整個產品命題的雛形，只是先套用在自己身上。
