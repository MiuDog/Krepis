# Focused Architecture Diagram

先回答使用者真正想看的是哪一種關係，再畫圖。不要把所有架構視角塞進同一張圖。

## 工作流程

1. 鎖定目標與問題。
   - 從使用者點名的功能、類別、模組、流程或檔案開始。
   - 目標明確時直接調查；只有範圍會實質改變答案時才一次問清楚。
   - 明定核心區域、直接上下游與不納入範圍。
2. 以搜尋與局部閱讀建立證據。
   - 優先搜尋符號定義、引用、建構點、介面實作、事件發送／訂閱及測試。
   - 大檔先搜尋定位再分段讀取。
   - 節點名稱使用程式中的真實名稱；找不到的關係標示「未查證」，不要補想像中的層。
3. 選擇一個主要架構視角；必要時加一個輔助視角。
4. 讀取 [Mermaid patterns](references/mermaid-patterns.md) 中對應的單一章節，再產生圖。
5. 將圖放入 Markdown，補上範圍、證據與閱讀說明。
6. 驗證 Mermaid 語法、節點與來源後，在 VS Code 預覽。

## 架構視角判定

| 使用者真正想知道的事 | 主要視角 | Mermaid 類型 |
| --- | --- | --- |
| 有哪些類別、介面，彼此如何組合或繼承 | 類別架構 | `classDiagram` |
| 模組、套件、分層或 library 誰依賴誰 | 模組／依賴架構 | `flowchart TD` |
| 一個操作從入口依序呼叫到哪裡 | 呼叫鏈／互動時序 | `sequenceDiagram` |
| 資料從哪裡來，經過哪些轉換後到哪裡 | 資料流架構 | `flowchart LR` |
| 事件由誰發出、誰訂閱、如何回應 | 事件架構 | `flowchart LR`；時序重要時用 `sequenceDiagram` |
| 物件或流程有哪些狀態與轉移條件 | 狀態架構 | `stateDiagram-v2` |
| 非同步工作、執行緒或程序如何協作 | 並行／執行架構 | `sequenceDiagram` |
| 服務、程序、儲存與外部系統如何部署 | 執行期／部署架構 | `flowchart TD` 搭配 `subgraph` |
| 資料實體、擁有權或關聯如何組成 | 資料模型架構 | `erDiagram` 或 `classDiagram` |

若使用者只說「架構」，依問題中的動詞判斷：

- 「有哪些、怎麼組成、誰依賴誰」偏靜態結構。
- 「怎麼走、先後順序、誰呼叫誰」偏呼叫鏈。
- 「資料怎麼變、事件怎麼傳」偏資料流或事件架構。
- 「何時切換、生命週期」偏狀態架構。

仍有兩種同樣合理的視角時，先說明判定並選最能回答核心問題的一種；只有兩張圖各自回答不同必要問題時才畫第二張。

## 裁切核心區域

- 一張圖只回答一個問題，預設不超過 12 個節點。
- 只保留指定核心、直接呼叫者、直接被呼叫者與必要邊界；通常最多向外延伸一層。
- 把第三方服務、資料庫、UI 或作業系統視為邊界節點，不展開其內部。
- 次要細節改放「閱讀說明」，不要用更多節點填滿圖。
- 超過 12 個必要節點時，拆成一張總覽與一張核心細節圖。

## 產出格式

使用者要求建立檔案時，優先遵循專案既有文件位置；沒有慣例時使用
`docs/architecture/<target>-<view>.md`。只要求解釋時，直接在回覆中提供相同結構。

````markdown
# <目標>：<架構視角>

## 範圍

- 核心問題：<這張圖回答什麼>
- 納入：<核心與直接邊界>
- 不納入：<刻意省略的部分>

## 架構圖

```mermaid
<diagram>
```

## 證據

- `path/to/file:line`：<支持哪個節點或關係>

## 閱讀說明

- <箭頭、邊界或推論的必要解釋>
````

圖中使用 ASCII 節點 ID 與真實名稱標籤。關係線標示具體動作，例如 `calls`、`implements`、
`publishes`、`reads` 或實際函式名稱；不要只寫模糊的 `uses`。

## VS Code 呈現

- 把 Mermaid 放在 `.md` 的 `mermaid` fenced code block 中，不另存無上下文的圖片。
- 使用 `Markdown: Open Preview to the Side` 或 `Ctrl+Shift+V` 開啟預覽。
- 若專案已有 Mermaid 擴充套件，沿用其預覽命令；不要為單張圖擅自改全域設定。
- 預覽工具不可用時仍交付 Markdown 原始碼，並明確標示「未進行視覺預覽」。

## 驗收

- 確認選定的架構視角能直接回答核心問題。
- 確認每個節點與主要箭頭都有來源證據，推論已清楚標示。
- 確認核心區域一眼可辨、方向一致、節點不超過 12 個。
- 確認 Mermaid fence 成對、節點 ID 唯一、含標點的標籤已加引號。
- 有 Mermaid CLI、編輯器預覽或其他現成渲染器時實際渲染；沒有時不要宣稱已視覺驗證。
- 建立檔案後回報路徑、採用的架構視角、納入範圍與驗證結果。
